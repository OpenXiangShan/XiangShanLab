### Describe the bug

While running vector tests against NEMU, I noticed that vector load instructions (like vle32.v) execute without raising an illegal instruction trap even when vtype is configured with a reserved/unsupported vsew encoding (e.g., vsew >= 0b100).

### Expected behavior

Per Section 3.4.2 of the RISC-V Vector Spec, setting an illegal or reserved vsew in vtype should mark vill = 1. Any subsequent vector instruction using that configuration ought to raise an illegal instruction trap immediately.
