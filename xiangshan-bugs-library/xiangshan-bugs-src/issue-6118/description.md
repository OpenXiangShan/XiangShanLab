The change moves the banked DCache target from 8 8-byte banks to 32 2-byte banks, packs all logical ways of each physical data bank into one SRAM row(not support wpu and SramedDataArray).
Precise bank conflict handling for 2B data is implemented on load read, store read/write, and AMO read/write operations.
In addition, the original layout of the ECC controller is [ECCCTL | ECCEID | ECCMASK0–7], with each ECCMASK 64 bits wide. Simply adding more ECCMASK registers cannot meet the constraint that the memory space allocated for ECC control is only 128 bytes. Leveraging the existing characteristic that ECCMASK0 is shared for tag and data error injection and its width far exceeds 2 bytes, we redesigned the ECC control register layout to [ECCCTL | ECCEID | TAGMASK | ECCMASK0–31], where each new ECCMASK register is 2 bytes wide.In fact, the width of each current bank is wayNums × (eccBits, dataBits). Although this approach results in extra overhead for ECC, practical testing has verified that adopting the format (eccBits, wayNums × dataBits) yields negative performance gains, as it requires reading out original data via readline and recalculating ECC on every access.For MBIST, to accommodate the scenario where a physical bank contains multiple ways, the MBIST mechanism only verifies an entire bank without fine-grained per-way checking.
