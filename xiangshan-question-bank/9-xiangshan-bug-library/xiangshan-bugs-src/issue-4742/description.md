* This patch is to solve the problem that the csr read instruction reads the value of `xtopi` into the general register, and the general register diff of XiangShan and NEMU is wrong.
* There is such a situation. We read `xtopi` into the general register through the csr read instruction. Since XiangShan and NEMU perform diff when the instruction is submitted. If the value of `xtopi` changes before the csr read instruction is submitted, NEMU gets the new `xtopi` value, which causes the diff of XiangShan and NEMU to be wrong.
* To solve this situation, the previous modification commit: 8f200f145e7a966198e818c53a50a3336267cfcf.
* I added a set of `old_xtopi` in NEMU. When the csr read instruction reads `xtopi`, it reads the old value of `xtopi`. After the csr instruction is executed, `old_xtopi` is synchronized. This modification partially solves the problem of reading `xtopi` to the general register diff error.
* However, there is still a situation where the value of `xtopi` changes after the previous CSR instruction is submitted. Since the synchronization of `old_xtopi` in NEMU requires a CSR instruction, if the next CSR read instruction happens to read `xtopi` to a general register, then the `xtopi` in XiangShan is the correct value, but the value of `xtopi` read by csr in NEMU is still `old_xtopi`, resulting in a diff error.
* In order to solve the diff problem, temporarily skip the csr read instruction to read the value of `xtopi` to the general register.
