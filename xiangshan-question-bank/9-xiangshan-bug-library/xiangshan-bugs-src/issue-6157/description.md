### Describe the bug

During a frontend redirect, FTQ suppresses the normal prediction-entry enqueue and backend enqueue paths, but it still accepts delayed BPU s3 metadata and writes that metadata into the FTQ metadata arrays.

The relevant behavior is:

- `bpuEnqueue` is qualified by `!redirect.valid`.
- `io.toBackend.wen` is qualified by `!redirect.valid`.
- `metaQueueRedirect`, `metaQueueResolve`, `metaQueueCommit`, and `perfQueue`
  are written under `when(io.fromBpu.meta.valid)` without an equivalent
  redirect guard.

As a result, in a redirect cycle XiangShan can write delayed BPU metadata into an FTQ slot that lies inside the redirect-flushed circular interval `[newEntryPtr, old bpuPtr)`. That slot no longer represents a valid surviving
fetch entry. The same metadata arrays later feed BPU redirect recovery, resolve training, and commit metadata.

The attached bare-metal testcase triggers repeated call/return frontend redirects:

```text
li t0, 0x82000000
ld t1, 0(t0)
addi t1, t1, 1
.rept 96
  jal ra, 1f
1:
.endr
jalr x0, 0(ra)
done:
  j done
```

The independent VCD monitor checks this predicate:

```text
redirect_valid && from_bpu_meta_valid && !bpuEnqueue && !toBackend_wen &&
  s3FtqPtr in circular interval [newEntryPtr, old bpuPtr)
```

The reproduced monitor result is:

```json
{
  "redirect_cycles": 65,
  "meta_valid_cycles": 324,
  "meta_valid_during_redirect": 58,
  "meta_valid_during_redirect_without_enqueue": 58,
  "meta_valid_for_redirect_flushed_entry": 58,
  "prediction_fire_during_redirect": 3
}
```

Representative event at VCD time `1077`:

```json
{
  "redirect_valid": 1,
  "from_bpu_meta_valid": 1,
  "bpu_enqueue": 0,
  "to_backend_wen": 0,
  "new_entry_ptr": [0, 5],
  "old_bpu_ptr": [1, 2],
  "from_bpu_s3_ptr": [1, 0],
  "flushed_span_from_new_entry_to_old_bpu_ptr": 5,
  "s3_distance_from_new_entry_ptr": 3
}
```

Since `3 < 5`, the delayed BPU metadata target lies inside the redirect-flushed FTQ interval. The normal enqueue paths for that slot are suppressed in the same cycle.

### Expected behavior

When a redirect flushes FTQ entries, delayed BPU metadata for entries in the flushed interval should not be accepted into `metaQueueRedirect`, `metaQueueResolve`, `metaQueueCommit`, or `perfQueue`.

The expected invariant is:

```text
if redirect invalidates an FTQ slot, same-cycle delayed BPU metadata must not
update metadata arrays for that invalidated slot
```

Equivalently, the FTQ metadata write path should be guarded consistently with the prediction-entry/backend enqueue paths, or should otherwise prove that the incoming `s3FtqPtr` still names a surviving entry.
