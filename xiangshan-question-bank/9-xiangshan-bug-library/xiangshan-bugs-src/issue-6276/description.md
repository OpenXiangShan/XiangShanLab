### Describe the bug

In the IMSIC, a VS-mode claim strobe (generated by a `vstopei` write / EOI) is driven to **all** guest interrupt files simultaneously, rather than only to the single guest interrupt file selected by `hstatus.VGEIN`. As a result, one guest's EOI clears the current top pending bit of **every** other guest interrupt file that holds one, permanently and silently dropping MSIs targeted at other virtual harts.

The read path (`vstopei` read) and the indirect-CSR read/write paths are correctly one-hot gated by `vgein`. The claim path is the only VS→IntFile path that is **not** gated — it is broadcast.

**1. CSR side — `vsClaim` is a bare "a vstopei write happened" pulse, with no per-guest demux by `vgein`.**

`NewCSR.scala`:
```scala
toAIA.mClaim  := mtopei.w.wen
toAIA.sClaim  := stopei.w.wen
toAIA.vsClaim := vstopei.w.wen   // no vgein term
```
`CSR.scala`:
```scala
imsic.fromCSR.vgein     := csrMod.toAIA.vgein   // vgein is plumbed...
imsic.fromCSR.claims(0) := csrMod.toAIA.mClaim
imsic.fromCSR.claims(1) := csrMod.toAIA.sClaim
imsic.fromCSR.claims(2) := csrMod.toAIA.vsClaim // ...but never ANDed into claims(2)
```

**2. IMSIC side — the single claims(2) is fanned out to all 7 guest interrupt files.**

`IMSIC.scala`:
```scala
val pi    = if (flati > 2) 2 else flati // index for privileges: M, S, VS.
...
intFile.fromCSR.claim           := fromCSR.claims(pi)
```
Compare with the read/write paths in the same loop, which ARE gated per file:
```scala
intFile.fromCSR.addr.valid      := sel_addr(fromCSR.addr).valid    // uses intFilesSelOH_r(flati)
intFile.fromCSR.wdata           := sel_wdata(fromCSR.wdata)         // uses intFilesSelOH_w(flati)
```

**3. IntFile — claim unconditionally clears its own top pending; it never consults vgein.**
`IMSIC.scala`:
```scala
when(fromCSR.claim) {
  val index  = toCSR.topei(params.imsicIntSrcWidth - 1, params.xlenWidth)
  val offset = toCSR.topei(params.xlenWidth - 1, 0)
  eips(index) := eips(index) & ~UIntToOH(offset)   // clears THIS file's own top
}
```


### Expected behavior

Gate the guest claim by vgein, matching what the read/write paths already do.
