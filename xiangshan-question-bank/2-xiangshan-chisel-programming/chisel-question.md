5.  **Non-blocking Cache设计与验证**
    设计一个支持多 outstanding miss 的 Non-blocking Cache，用于连接CPU（只读不写）和内存。
    -   CPU请求的物理地址宽度为 48 位（假设为 RV64）。
    -   内存接口为 64 位。
    -   数据缓存规格：16-KB，4 路组相连，64 字节行大小。
    **要求：**
    1.  替换算法可任意选择。
    2.  至少支持 4 个 miss 请求而不阻塞。
    3.  给出 RTL 代码（Chisel、SystemVerilog 或 VHDL 均可）、验证代码和结果，并撰写文档说明所做的工作。
6.  **Page Table Walker (详细题目)**
    在现代操作系统中，虚拟内存管理通常使用多级页表来高效管理内存。现需实现一个进行页表查询的 Page Table Walker。通过给定的 32 位虚拟地址和页表，找到对应的 34 位物理地址。
    -   编程语言不限。
    -   每级页表含有 2^10 个表项，每个表项为 32 位。
    -   页表项分为叶节点和中间节点，使用 L 位标明该节点是否为叶节点。中间节点存储下一级页表的基地址，叶节点存储物理页号。
    -   页大小有 4KB 和 4MB 两种可能。
    -   特殊状态寄存器存储二级页表的基地址，以及是否开启物理地址转换的开关。若未开启，则直接输出虚拟地址作为物理地址返回。
    -   无需考虑页表项无效的情况。如果在查表过程中出现地址宽度不足，可以通过在 32 位地址前填充两个 0 来扩展为 34 位。

    **特殊状态寄存器结构**

    | 名称 | 开启？MODE | 物理页号 PPN |
    | :--- | :---: | :---: |
    | 宽度 | 1 | 22 |

    **虚拟地址结构**

    | 名称 | 虚拟页号 段1<br>VPN[1] | 虚拟页号 段0<br>VPN[0] | 页内偏移<br>Page Offset |
    | :--- | :---: | :---: | :---: |
    | 宽度 | 10 | 10 | 12 |

    **物理地址结构**

    | 名称 | 物理页号 段1<br>PPN[1] | 物理页号 段0<br>PPN[0] | 页内偏移<br>Page Offset |
    | :--- | :---: | :---: | :---: |
    | 宽度 | 12 | 10 | 12 |

    **页表项结构**

    | 名称 | 物理页号 段1<br>PPN[1] | 物理页号 段0<br>PPN[0] | ZERO RSW |
    | :--- | :---: | :---: | :---: |
    | 宽度 | 12 | 10 | 9 |
    *ZERO RSW 为全 0，无功能。*

    **查表请求输入**
    1.  32 位的虚拟地址

    **特殊状态寄存器输入**
    1.  二级页表的基地址
    2.  虚拟地址转换的开启/关闭状态

    **内存请求输入**
    1.  **34 位物理地址**

    **内存返回**
    1.  32 位页表项

    **查表请求返回**
    1.  34 位物理地址

    **提示：** 节点分为中间节点和叶节点，页分为 4KB 和 4MB，它们之间的联系是什么？
    参考：[https://en.wikipedia.org/wiki/Page_table](https://en.wikipedia.org/wiki/Page_table)

8.  **AXI3 双主仲裁 Crossbar 设计与验证**
    设计一个 AXI3 2-to-1 Crossbar，用于连接两个主设备和一个从设备。两个主设备分别代表取指侧和数据访存侧，允许同时发起读写请求。
    -   地址宽度为 32 位，数据宽度为 32 或 64 位均可。
    -   两个主设备的事务 ID 范围不得重叠。
    -   需要支持 AR / R / AW / W / B 五个通道的独立握手。
    **要求：**
    1.  请求通道需要支持锁定式仲裁，避免 burst 传输过程中被其他主设备打断。
    2.  响应通道需要按照事务 ID 正确返回到发起请求的主设备。
    3.  需要给出随机或定向测试，覆盖读写并发、burst 末拍释放、以及一侧持续请求时另一侧不饥饿等场景。
    4.  给出 RTL 代码、验证代码和文档，说明仲裁策略与关键时序。
9.  **两级分支预测器设计与验证**
    设计一个适用于 RISC-V 处理器前端的轻量级分支预测器。预测器由 BTB 和 2-bit 饱和计数器表组成，用于预测一拍内取回的一组指令中是否存在跳转目标。
    -   取指宽度为 4。
    -   BTB 容量、PHT 容量可自行设定，但需要在文档中说明设计取舍。
    -   不要求支持复杂的返回地址栈恢复机制。
    **要求：**
    1.  能够输出是否预测跳转、跳转目标以及命中的指令偏移。
    2.  需要支持基于实际执行结果的更新，包括 BTB 新建、命中更新和 PHT 训练。
    3.  需要考虑跨取指块场景，说明如何处理“当前块”和“下一块”的候选跳转。
    4.  给出 RTL 代码、验证代码和结果，并撰写文档说明预测准确率和局限性。
10.  **可回滚 Rename 快照管理器**
    为一个支持乱序执行的 RISC-V 处理器实现 Rename 快照管理器，用于配合寄存器重命名表和空闲物理寄存器表在分支预测下进行状态保存与恢复。
    -   处理器每拍最多重命名 3 条指令。
    -   最多同时维护 8 个快照槽位。
    -   某些分支解析为误预测后，需要恢复到指定快照，并释放所有更年轻的快照。
    **要求：**
    1.  支持同拍多条指令申请快照，并为它们分配唯一编号。
    2.  支持“正确预测仅释放自身”和“误预测释放自身及所有更年轻快照”两种解析模式。
    3.  需要输出恢复控制信号，供 Rename Table 和 Free List 协同回滚。
    4.  给出 RTL 代码、验证代码和文档，重点说明年龄关系维护方法与边界场景处理。
11.  **多端口环形队列设计与验证**
    设计一个通用环形队列模块，供 RISC-V 处理器中的指令缓冲、ROB 或调度缓冲等场景复用。
    -   队列深度为 8 或 16，可自行选择，但必须是 2 的幂。
    -   支持每拍最多 4 路入队、最多 3 路出队。
    -   需要提供 `empty`、`full`、`count` 和按索引随机读接口。
    **要求：**
    1.  支持同拍多入队、多出队，并正确维护头尾指针。
    2.  需要支持 `flush` 清空功能。
    3.  需要说明在“前面端口无效、后面端口有效”这类不连续输入场景下如何处理。
    4.  给出 RTL 代码、验证代码和文档，覆盖空队列、满队列、回卷、同拍进出队等边界情况。
12.  **取指缓冲 IBuffer 设计与验证**
    设计一个面向处理器前端的指令缓冲模块，用于接收一拍内取回的一组指令，并按后端可接受的宽度送出。
    -   前端每拍最多输入 4 条指令。
    -   后端每拍最多消费 3 条指令。
    -   每条指令除指令字外，还需携带 PC 和少量附带元信息。
    **要求：**
    1.  需要支持块状入队，即一拍输入的多条指令应作为同一个取指块处理。
    2.  需要支持后端 redirect 时清空缓冲。
    3.  需要仔细处理多路 `ready` 传播，避免出现“后面的端口先出队、前面的端口没出队”的错误行为。
    4.  给出 RTL 代码、验证代码和文档，重点说明握手设计与边界情况。
13.  **简化 MSHR 文件设计与验证**
    设计一个简化版 MSHR 文件，用于支持 Non-blocking DCache 处理多个并发 miss。
    -   支持 2 个 Primary MSHR。
    -   支持 4 个 secondary 表项，用于挂接命中同一 cache block 的后续请求。
    -   只需支持普通 load/store miss，不要求支持原子操作。
    **要求：**
    1.  需要区分“首个 miss 分配新的 primary”与“后续 miss 合并到已有 primary”两种情况。
    2.  需要能够跟踪 secondary 请求的元信息，并在 refill 完成后逐个唤醒。
    3.  需要支持 redirect 或 flush 后清除无效的年轻 load 请求。
    4.  给出 RTL 代码、验证代码和文档，说明 primary/secondary 关系以及冲突场景处理。
14.  **简化双端口地址翻译单元**
    设计一个简化的地址翻译单元，分别服务于取指请求和数据访存请求。
    -   支持 direct map 和分页模式两种工作状态。
    -   分页模式下，使用一个可查询的 TLB 作为后端翻译资源。
    -   访存侧需要区分 load/store，并检测地址未对齐异常。
    **要求：**
    1.  取指侧和数据侧需要各自独立握手，互不阻塞。
    2.  需要根据翻译结果输出物理地址、cacheable 属性和异常信息。
    3.  需要支持 flush，将在途请求清空并使状态机返回空闲态。
    4.  给出 RTL 代码、验证代码和文档，重点说明状态机与异常判定逻辑。
15.  **多队列 Dispatch 分发器**
    设计一个简化 Dispatch 模块，将重命名后的指令按照功能类型分发到多个 Issue Queue。
    -   输入宽度为 3。

    **要求：**

    3.  需要保证更老指令因资源不足被阻塞时，不会错误地让更年轻相关指令越过。
    4.  给出 RTL 代码、验证代码和文档，说明分流策略、阻塞条件和公平性考虑。
