4.  **RISC-V Matrix Extension**
    **题目：**
    RISC-V 矩阵扩展是一种用于加速矩阵运算的指令集扩展。NEMU-Matrix 是一个基于 NEMU 修改的、支持该扩展的指令级模拟器。

    **目标：**
    请你通过阅读该扩展的文档和代码，理解矩阵扩展的指令格式与行为，使用 Python 构建一个**自动化测试程序生成器**，能够：
    1.  随机生成一段合法的 RISC-V 汇编代码或 C 代码（内联汇编），其中必须包含对 RISC-V 矩阵扩展指令的调用。
    2.  自动调用给定的编译器 (`triton-cpu-llvm-install-self-define`) 将生成的汇编/C 代码编译为 RISC-V 二进制程序 (ELF 或 BIN)。
    3.  将该二进制程序载入 NEMU-Matrix 模拟器中运行，并捕获运行结果（如日志、模拟器退出状态等）。
    4.  使用 YAML 或 Mako 等模板来结构化描述指令信息。
    5.  其余功能可自行扩展。

    **提交内容：**
    -   Python 源代码（以及必要的辅助脚本）。
    -   一份简短的 README.md。
    -   一个生成并运行成功的测试用例输出样例（日志、汇编代码、二进制文件等）。

    **资源链接：**
    -   [https://github.com/OpenXiangShan/NEMU](https://github.com/OpenXiangShan/NEMU)

6. **AXI3 Crossbar 验证**
    为一个连接“取指侧主设备”和“数据侧主设备”的 AXI3 2-to-1 Crossbar 制定验证方案。
    1.  说明需要覆盖哪些基础功能：读通路、写通路、burst 传输、ID 路由、仲裁切换。
    2.  说明需要重点覆盖哪些时序边界：`ready` 拉低、`wlast` 释放、双主同时请求、长时间单侧占用。
    3.  设计至少 3 个定向测试，以及 1 个随机测试或约束随机测试。
    4.  说明如何判断响应被错误路由，如何在波形或日志中快速定位问题。
7. **分支预测器验证**
    针对一个由 BTB + 2-bit 饱和计数器组成的分支预测器，设计验证方案。
    1.  需要覆盖冷启动、BTB 未命中、命中但预测不跳转、命中且预测跳转、更新训练后状态翻转等场景。
    2.  需要考虑一拍取回多条指令时，预测命中的偏移是否正确。
    3.  说明如何构造跨取指块、块内多个控制流候选等边界场景。
    4.  给出参考模型思路，说明如何对比 RTL 输出与软件模型输出。
8. **乱序核重定向恢复验证**
    为一个包含 Rename、ROB、Issue Queue、Load/Store Queue 的乱序 RISC-V 处理器设计重定向恢复验证方案。
    1.  说明如何构造“分支误预测恢复”“异常恢复”“提交阶段 redirect”三类核心场景。
    2.  说明恢复后需要检查哪些状态一致性：物理寄存器映射、ROB 队列内容、Issue Queue 有效项、LSQ 中年轻指令清除情况。
    3.  给出至少一个会同时覆盖“前端已取到错误路径指令”和“后端已有错误路径指令在飞”的测试思路。
    4.  说明如何借助参考模型、提交日志或波形信号判断恢复是否精确。
9. **TLB 与 Page Table Walk 验证**
    针对包含 TLB、Page Table Walker 和权限检查逻辑的地址翻译模块，建立参考模型和可重复的验证环境。
    1.  覆盖命中、冷启动 miss、多级页表遍历、超级页、Page Fault、Access Fault、权限切换和 `sfence.vma`。
    2.  设计定向与随机测试，重点检查旧映射不可复用、连续 miss 的处理顺序以及翻译结果与 Cache 请求的对应关系。
    3.  通过断言或 scoreboard 检查 PPN、权限、异常原因、回填内容和请求响应握手，提交覆盖率与典型波形。
10. **乘除法功能单元验证**
    针对包含 Booth 乘法器、SRT 除法器或开方器的执行单元，验证结果正确性、变长延迟和乱序交互。
    1.  覆盖有符号/无符号、零、最大最小值、溢出、除零、余数和开方边界，并与软件参考模型逐项比对。
    2.  检查固定延迟乘法与变长除法的 `valid/ready`、阻塞、取消、异常和结果返回时序。
    3.  构造背靠背依赖和无关指令并行执行场景，确认依赖能正确唤醒、长延迟单元不会阻塞无关指令。
    4.  区分算术结果错误、操作数错误和时序错误，说明如何用日志、断言和波形定位。
11. **Cache 一致性协议验证**
    为实现 MSI、MESI、MESIF 或 MOESI 的多核缓存系统建立状态机级和系统级验证方案。
    1.  覆盖状态迁移、共享/独占获取、写权限升级、失效广播、脏数据回写、替换和目录更新。
    2.  设计至少 3 个多核场景：读后写竞争、写后读共享、回写与失效交叉；再加入随机并发访问测试。
    3.  使用参考模型、协议断言和事务 scoreboard 检查 Cache Line 状态、目录状态、响应路由及最终内存值。
    4.  对仅在高并发或特定时序下出现的错误，给出日志压缩、事务追踪和波形定位方法。
