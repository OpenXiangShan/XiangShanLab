# Issue #6267 图解：Store Queue 为什么会死锁

下面的图只保留理解这个问题所需的几个概念：ROB 负责按程序顺序提交，Store Queue 保存尚未完成的 store，virtual queue 和 physical queue 必须保持一致。

### 正常的 store 流程

```text
程序指令
   │
   ▼
┌──────┐    ┌──────────────┐    ┌────────────┐    ┌────────┐
│ 执行 │ →  │ Store Queue  │ →  │ 内存访问   │ →  │ 提交   │
└──────┘    └──────────────┘    └────────────┘    └────────┘
```

ROB 可以看作“总订单队列”：后面的指令可以提前准备，但必须等前面的指令按顺序提交。Store Queue 可以看作“待发货仓库”：包裹必须从队头依次发出，后面的包裹不能越过队头。

### 异常 store 的正常处理

```text
┌──────────────┐
│ store 访问错误│
└──────┬───────┘
       ▼
┌──────────────┐
│ 标记异常      │
└──────┬───────┘
       ▼
┌──────────────┐
│ 通知 ROB      │
└──────┬───────┘
       ▼
┌──────────────┐
│ redirect     │
└──────┬───────┘
       ▼
┌──────────────┐
│ 清除异常 entry│
└──────┬───────┘
       ▼
┌──────────────┐
│ 异常处理程序  │
└──────────────┘
```

### 本问题的第一步：异常 vector store 入队

```text
Virtual Store Queue:

┌──────────────┐
│ entry 4      │
│ isVec = 1    │
│ reqNum = 4   │
│ ROB = 145    │
└──────┬───────┘
       │ 占用 4 个 physical slot
       ▼

Physical Store Queue:

索引       4       5       6       7       8       9
        ┌───────┬───────┬───────┬───────┬───────┬───────┐
        │ ROB145│ ROB145│ ROB145│ ROB145│       │       │
        │ vec   │ vec   │ vec   │ vec   │       │       │
        └───────┴───────┴───────┴───────┴───────┴───────┘
          ▲
          └─ physical queue head
```

### 第二步：vector store 出错

```text
槽 4       槽 5       槽 6       槽 7
┌────────┬────────┬────────┬────────┐
│异常    │异常    │异常    │异常    │
│E = 1   │E = 1   │E = 1   │E = 1   │
│C = 0   │C = 0   │C = 0   │C = 0   │
└────────┴────────┴────────┴────────┘

E = hasException
C = committed
```

### 第三步：virtual queue 提前释放

```text
Virtual queue                         Physical queue

之前                                     之后
┌──────────────┐                        ┌────┬────┬────┬────┐
│ entry 4      │ ── vecMbCommit ─────▶ │ E  │ E  │ E  │ E  │
│ ROB145       │                        │C=0 │C=0 │C=0 │C=0 │
│ 有异常       │                        └────┴────┴────┴────┘
└──────────────┘

virtual entry 被释放，retirePtr: 4 ─────────▶ 8
physical 槽位却仍然存在。
```

### 第四步：redirect 保留了异常槽

```text
索引       4       5       6       7       8       9
        ┌───────┬───────┬───────┬───────┬───────┬───────┐
        │ 保留  │ 保留  │ 保留  │ 保留  │ 取消  │ 取消  │
        └───────┴───────┴───────┴───────┴───────┴───────┘
          ◀──────────── [4,8) ────────────▶

异常槽 4..7 没有被清除；槽 8 之后才被取消。
```

### 第五步：队头没有任何出口

```text
队头
  │
  ▼
┌───────┬───────┬───────┬───────┬─────────┬─────────┐
│异常   │异常   │异常   │异常   │ fsw     │ 后续    │
│ROB145 │ROB145 │ROB145 │ROB145 │ROB187   │ store   │
└───────┴───────┴───────┴───────┴─────────┴─────────┘
  ✖       ✖       ✖       ✖        等待
```

```text
异常队头
   │
   ├─ commit       ✖ hasException=1 被排除
   ├─ writeback    ✖ 没有可用路径
   ├─ uncache      ✖ 需要 hasException=0 且 committed=1
   ├─ vector retire✖ virtual entry 已释放
   └─ redirect     ✖ 槽位在保留区间 [4,8)

                 ↓

              永久卡死
```

### 第六步：`fsw` 只是后面的受害者

```text
fsw:

┌──────────────────────────────────────┐
│ PC     = 0x800013bc                  │
│ 地址   = 0x2cc                       │
│ ROB    = 187                         │
│ 已完成地址和数据准备                  │
└──────────────────┬───────────────────┘
                   │
                   ▼
       前面还有异常槽 4..7
       Store Queue 不允许越过它们
```

```text
最后提交：

0x800013b4 ──▶ 0x800013b8 ──▶ 停止
                                  │
                                  ▼
                         0x800013bc 的 fsw
                         永远无法提交
```

### 根因总图

```text
异常 vector store
        │
        ▼
virtual queue 过早释放
        │
        ▼
physical queue 仍保留异常槽
        │
        ▼
redirect 没有取消异常槽
        │
        ▼
异常槽成为永久队头
        │
        ▼
fsw 和后续 store 无法出队
        │
        ▼
ROB 停止提交
        │
        ▼
deadlock
```

```text
┌─────────────────────────────────────────────────────────────┐
│ virtual queue： “这个异常 store 已经处理完了。”              │
│ physical queue：“它还在我的队头。”                           │
│                                                             │
│ 两边状态不一致，队头既不能提交，也不能清除。                 │
│ 后面的 fsw 只是被这个坏 entry 堵住的受害者。                  │
└─────────────────────────────────────────────────────────────┘
```
