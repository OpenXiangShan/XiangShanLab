# MESI

MESI 用四种状态描述一条缓存行在某个 Cache 中是否有效、能否写入，以及最新数据在哪里。

## 1. 先认识四种状态

| 状态 | 直观含义 | 能否读取 | 能否直接写入 |
|---|---|---:|---:|
| `M`（Modified） | 只有我有，而且我改过 | 能 | 能 |
| `E`（Exclusive） | 只有我有，而且我没改过 | 能 | 能 |
| `S`（Shared） | 其他 Cache 可能也有 | 能 | 不能 |
| `I`（Invalid） | 我这里没有可用副本 | 不能 | 不能 |

### 1.1 `M`：唯一，而且修改过

当前 Cache 是唯一持有者，数据已经被本地核心修改，内存中的值还是旧的。本地可以直接读写，但不能直接丢弃这条缓存行，因为最新数据只在这里。

### 1.2 `E`：唯一，但没有修改过

当前 Cache 是唯一持有者，数据与内存相同。本地可以直接读写。第一次写入时，状态直接从 `E` 变成 `M`，不需要通知其他 Cache。

### 1.3 `S`：可能有多个副本

当前 Cache 中的数据有效，可以读取，但其他 Cache 也可能持有相同副本。因此，本地不能直接写入；写入前必须先让其他副本失效。

### 1.4 `I`：当前副本不能使用

当前 Cache 没有可用副本。本地读取时需要重新取得数据；本地写入时还要取得唯一写权限。

下面不再逐条背状态转移，而是跟着缓存行 `X` 在两个核心之间走一遍。理解了这个故事，也就理解了 MESI 的主要状态变化。

## 2. 缓存行 `X` 的旅程

Core 0 和 Core 1 各有一个私有 Cache。系统中还有一个目录（Directory），它记录哪些 Cache 持有某条缓存行，并负责协调权限转移。目录发送的 Snoop，是要求某个 Cache 检查本地副本，并按要求降级、失效或返回最新数据。

内存中的 `X` 初始值为 `0`，两个 Cache 中都没有 `X` 的有效副本：

```text
Core 0: I
Core 1: I
内存:   X=0
```

### 2.1 Core 0 第一次读取：`I -> E`

Core 0 要读取 `X`，但它的 Cache 中没有有效副本，于是向目录发起读请求。目录发现当前没有任何 Cache 持有这条缓存行，便让内存返回 `X=0`，并把 Core 0 记录为唯一持有者。

此时其他 Cache 没有这条缓存行，所以 Core 0 是唯一持有者。数据也没有被修改，仍与内存相同。因此，Core 0 得到的状态是 `E`：

```text
Core 0: I -> E, X=0
Core 1: I
内存:   X=0
```

这里出现了第一个变化：

> `I -> E`：取得一份只有自己持有、并且尚未修改的数据。

### 2.2 Core 1 也来读取：`E -> S`、`I -> S`

接着，Core 1 也要读取 `X`。Core 1 当前是 `I`，于是向目录发起读请求。

目录发现 Core 0 持有 `E`，便向 Core 0 发送 Snoop，通知它这条缓存行将被共享。Core 0 收到 Snoop 后从 `E` 降为 `S`，并返回响应。随后 Core 1 得到数据并进入 `S`，目录把 Core 0 和 Core 1 都记录为共享者：

```text
Core 0: E -> S, X=0
Core 1: I -> S, X=0
内存:   X=0
```

这里同时出现了两个变化：

> `E -> S`：原来的唯一副本变成共享副本。

> `I -> S`：新读取者取得一份共享副本。

现在两个核心都能读 `X`，但谁都不能直接写，因为对方手里还有一份副本。

### 2.3 Core 0 写入：`S -> M`、`S -> I`

Core 0 现在要把 `X` 改成 `1`。

Core 0 不能直接修改自己的 `S` 副本。否则，Core 1 仍会保留 `X=0`，下一次读取就可能看到旧值。Core 0 必须先向目录请求写权限。

目录查到这条缓存行当前由 Core 0 和 Core 1 共享。Core 0 自己不需要失效，因此目录向 Core 1 发送 Snoop，请求 Core 1 使本地副本失效。

整个过程如下：

1. Core 0 向目录请求把自己的共享权限升级为独占写权限。
2. 目录根据共享者记录，向 Core 1 发送失效 Snoop。
3. Core 1 收到 Snoop，把本地状态从 `S` 改为 `I`。
4. Core 1 向目录返回 Snoop 响应，确认副本已经失效。
5. 目录确认除 Core 0 外不再有其他有效副本，于是向 Core 0 授予写权限。
6. Core 0 收到写权限后，才能把 `X` 改成 `1`，并从 `S` 进入 `M`。

完成后的状态是：

```text
Core 0: S -> M, X=1
Core 1: S -> I
内存:   X=0
```

这里同时出现了两个变化：

> `S -> I`：其他共享副本收到目录发来的失效 Snoop 后变为无效。

> `S -> M`：写入者等到其他共享副本全部失效后，取得唯一写权限并修改数据。

注意，此时内存仍是 `X=0`。最新的 `X=1` 只在 Core 0 的 Cache 中，这正是 `M` 的含义。

### 2.4 Core 1 再次读取：`M -> S`、`I -> S`

Core 1 再次读取 `X`。它原来的副本已经是 `I`，不能继续使用，只能向目录重新请求数据。

目录知道 Core 0 持有 `M`，也知道内存中的 `X=0` 已经过期，因此不能直接让内存返回旧数据。目录向 Core 0 发送读 Snoop，要求它交出最新数据并把权限降为共享。Core 0 返回 `X=1`，从 `M` 降为 `S`；目录用这份数据响应 Core 1，并更新内存。Core 1 收到数据后进入 `S`：

```text
Core 0: M -> S, X=1
Core 1: I -> S, X=1
内存:   X=1
```

这里出现了：

> `M -> S`：唯一的脏副本把最新数据交出来，变成共享副本。

> `I -> S`：读取者取得最新的共享副本。

`M` 中保存的是最新数据，所以别的核心来读时，不能绕过它去使用内存中的旧值。

### 2.5 Core 1 写入：写权限转移给 Core 1

现在 Core 1 要把 `X` 改成 `2`。此时两个 Cache 都是 `S`，所以 Core 1 向目录请求写权限。目录向另一个共享者 Core 0 发送失效 Snoop；Core 0 从 `S` 变为 `I` 并返回确认。目录收到确认后授予 Core 1 写权限，Core 1 才能写入并进入 `M`：

```text
Core 0: S -> I
Core 1: S -> M, X=2
内存:   X=1
```

这与 Core 0 上一次写入的过程相同，但它说明了一件重要的事：

> 写权限不固定属于某个核心。谁要写，谁就必须成为唯一持有者。

现在最新的 `X=2` 只在 Core 1 中。

### 2.6 Core 0 直接写入：`I -> M`、`M -> I`

接下来，Core 0 不先读取，而是直接要把 `X` 改成 `3`。

Core 0 当前是 `I`，既没有数据，也没有写权限，于是向目录请求以可写方式取得这条缓存行。

目录查到最新的 `X=2` 在 Core 1 的 `M` 中，便向 Core 1 发送失效 Snoop，同时要求它返回最新数据。Core 1 交出 `X=2`，从 `M` 变成 `I`。目录用返回的数据更新内存，确认原持有者已经失效后，再把数据和唯一写权限交给 Core 0。Core 0 随后写入 `X=3`，进入 `M`：

```text
Core 0: I -> M, X=3
Core 1: M -> I
内存:   X=2
```

这里出现了两个关键变化：

> `M -> I`：原持有者交出最新数据和写权限，自己的副本失效。

> `I -> M`：新写入者同时取得数据和唯一写权限，然后完成写入。

这一步展示了写权限如何从一个核心直接转移到另一个核心。无论怎样转移，同一时刻都不能有两个 `M`。

### 2.7 Core 0 驱逐缓存行：`M -> I`

Core 0 的 Cache 需要腾出空间，准备驱逐 `X` 所在的缓存行。

当前 `X=3` 只存在于 Core 0 的 `M` 副本中。如果直接丢弃，系统就只剩下旧数据。因此，Core 0 必须先把 `X=3` 写回目录管理的内存，并通知目录自己不再持有这条缓存行，然后才能进入 `I`：

```text
Core 0: M -> I
Core 1: I
内存:   X=3
```

这里再次出现 `M -> I`，但原因不同：上一次是把数据和写权限交给另一个核心，这一次是把最新数据写回后主动驱逐。

两种情况遵守的是同一条规则：

> 离开 `M` 时，最新数据必须有明确去向，不能丢失。

### 2.8 Core 1 读取后写入：`I -> E -> M`

此时两个 Cache 都是 `I`。Core 1 再次读取 `X`，于是向目录发起读请求。目录确认当前没有其他持有者，让内存返回最新的 `X=3`，并把 Core 1 记录为唯一持有者。

因为没有其他 Cache 持有这条缓存行，Core 1 得到 `E`：

```text
Core 0: I
Core 1: I -> E, X=3
内存:   X=3
```

随后，Core 1 把 `X` 改成 `4`。

`E` 已经说明 Core 1 是唯一持有者，所以不需要通知其他 Cache，也不需要让任何副本失效。Core 1 可以直接修改数据并进入 `M`：

```text
Core 0: I
Core 1: E -> M, X=4
内存:   X=3
```

这里出现了：

> `E -> M`：唯一的干净副本被本地修改，静默变成脏副本。

这就是 `E` 状态的价值：它记录了“只有我有”这个事实，使第一次写入不需要额外的一致性通信。

## 3. 回看整个故事

缓存行 `X` 的旅程可以压缩成下面这张表：

| 步骤 | 操作 | Core 0 | Core 1 | 这一变化说明什么 |
|---|---|---|---|---|
| 1 | Core 0 读取 | `I -> E` | `I` | 第一个读取者得到唯一副本 |
| 2 | Core 1 读取 | `E -> S` | `I -> S` | 出现多个只读副本 |
| 3 | Core 0 写入 | `S -> M` | `S -> I` | 写入前使其他副本失效 |
| 4 | Core 1 读取 | `M -> S` | `I -> S` | `M` 持有者提供最新数据 |
| 5 | Core 1 写入 | `S -> I` | `S -> M` | 写权限转移给 Core 1 |
| 6 | Core 0 直接写入 | `I -> M` | `M -> I` | 数据和写权限直接转移 |
| 7 | Core 0 驱逐 | `M -> I` | `I` | 最新数据必须先写回 |
| 8 | Core 1 读取后写入 | `I` | `I -> E -> M` | 唯一副本可以直接写入 |


## 4. 从故事中记住四条规则

1. 多个 Cache 可以同时持有 `S`，一起读取同一条缓存行。
2. `M` 和 `E` 都表示唯一持有者，不能与其他有效副本同时存在。
3. 一个核心写入前，必须先让其他 Cache 中的有效副本变成 `I`。
4. `M` 中保存着最新数据；无论降级、转移还是驱逐，这份数据都不能丢失。

`M`、`E`、`S`、`I` 表示一次操作完成后的状态。真实硬件在等待数据或等待其他 Cache 失效时还会使用临时状态，本章不展开。



# MOESI

MOESI 使用 `M`、`O`、`E`、`S`、`I` 五种状态描述一条缓存行。前面已经解释过 `M`、`E`、`S`、`I`，这里重点认识新增的 `O`，然后通过一个完整故事理解五种状态如何配合。

## 1. `O` 状态是什么意思

| 状态 | 直观含义 | 能否读取 | 能否直接写入 |
|---|---|---:|---:|
| `O`（Owned） | 数据被修改过，由我负责，但其他 Cache 也可以有只读副本 | 能 | 不能 |

`O` 同时具有 `M` 和 `S` 的一部分特征：

- 像 `M` 一样，`O` 保存着比内存更新的数据，不能直接丢弃。
- 像 `S` 一样，`O` 允许其他 Cache 同时持有只读副本。
- 与 `S` 不同，`O` 是最新数据的负责人，其他共享者读取到的数据来自它所负责的版本。
- 与 `M` 不同，`O` 不是唯一副本，所以不能直接写入。

同一条缓存行可以出现下面的组合：

```text
一个 O + 一个或多个 S
```

但不能同时出现两个 `O`。目录必须知道谁是唯一的 Owner，以及哪些 Cache 是 Sharer。

`O` 使下面这种状态成为可能：多个 Cache 持有同一份最新数据，但内存仍是旧的。此时 Owner 负责这份最新数据，其他 `S` 只能读取，任何读请求都不能绕过 Owner 使用内存中的旧值。

## 2. 缓存行 `X` 的旅程

这次使用三个核心，才能完整看到“一个 `O` 带着多个 `S`”的状态。

Core 0、Core 1、Core 2 各有一个私有 Cache。目录记录 Owner 和 Sharer，并通过 Snoop 要求 Cache 降级、失效或返回最新数据。

初始状态仍然是：

```text
Core 0: I
Core 1: I
Core 2: I
内存:   X=0
```

### 2.1 Core 0 读取后写入：`I -> E -> M`

Core 0 先读取 `X`。目录确认没有其他持有者，让内存返回 `X=0`，并把 Core 0 记录为唯一持有者。Core 0 得到 `E`。

随后 Core 0 把 `X` 改成 `1`。因为 `E` 已经表示唯一持有者，所以 Core 0 不需要请求目录，直接从 `E` 进入 `M`：

```text
Core 0: I -> E -> M, X=1
Core 1: I
Core 2: I
内存:   X=0
```

现在最新数据只在 Core 0 中，目录记录 Core 0 是这条缓存行的唯一脏持有者。

### 2.2 Core 1 读取：`M -> O`、`I -> S`

Core 1 要读取 `X`，于是向目录发起读请求。

目录查到 Core 0 持有 `M`，而内存中的 `X=0` 已经过期，因此不能让内存直接响应。接下来发生：

1. 目录向 Core 0 发送读 Snoop。
2. Core 0 收到 Snoop，返回最新的 `X=1`。
3. Core 0 不再是唯一持有者，因此从 `M` 降为 `O`。
4. 目录把 Core 0 记录为 Owner，把 Core 1 记录为 Sharer。
5. Core 1 收到 `X=1`，从 `I` 进入 `S`。
6. 内存不更新，仍然保存旧的 `X=0`。

完成后的状态是：

```text
Core 0: M -> O, X=1
Core 1: I -> S, X=1
Core 2: I
内存:   X=0
```

这里出现了两个关键变化：

> `M -> O`：原来的脏数据持有者允许别人共享读取，但继续负责最新数据。

> `I -> S`：新读取者得到最新数据，但只拥有共享读权限。

### 2.3 Core 2 也来读取：`O -> O`、`I -> S`

接着，Core 2 也要读取 `X`，于是向目录发起读请求。

目录知道内存还是旧值，也知道最新数据由 Core 0 的 `O` 负责。因此：

1. 目录向 Owner，也就是 Core 0，发送读 Snoop。
2. Core 0 返回最新的 `X=1`，并继续保持 `O`。
3. 目录把 Core 2 加入共享者集合。
4. Core 2 收到 `X=1`，从 `I` 进入 `S`。

```text
Core 0: O, X=1
Core 1: S, X=1
Core 2: I -> S, X=1
内存:   X=0
```

此时全系统有三份相同的数据，但它们的责任不同：

- Core 0 的 `O` 是唯一 Owner，负责最新数据。
- Core 1 和 Core 2 的 `S` 只能读取。
- 内存仍然是旧的，不能绕过 Owner 返回 `X=0`。

这一步说明：

> `O` 可以保持不变，并继续为更多读取者提供最新数据。

### 2.4 Owner 写入：`O -> M`、`S -> I`

Core 0 现在要把 `X` 改成 `2`。

虽然 Core 0 是 Owner，但 Core 1 和 Core 2 仍持有 `S`。如果 Core 0 直接写入，这两个共享者就会保留旧的 `X=1`。因此，`O` 不能像 `M` 那样直接写。

Core 0 必须先重新取得唯一写权限：

1. Core 0 向目录请求写权限。
2. 目录查到 Core 1、Core 2 是共享者。
3. 目录分别向 Core 1、Core 2 发送失效 Snoop。
4. Core 1 和 Core 2 收到 Snoop，各自从 `S` 变成 `I`。
5. 两个核心分别向目录返回 Snoop 响应，确认副本已经失效。
6. 目录收齐全部响应，确认 Core 0 已经成为唯一持有者。
7. 目录向 Core 0 授予写权限，Core 0 从 `O` 进入 `M`。
8. Core 0 把 `X` 改成 `2`。

```text
Core 0: O -> M, X=2
Core 1: S -> I
Core 2: S -> I
内存:   X=0
```

这里出现了：

> `O -> M`：Owner 使所有共享副本失效后，重新成为唯一持有者。

> `S -> I`：共享者响应目录的失效 Snoop，放弃本地副本。

### 2.5 Core 1 再次读取：重新形成 `O + S`

Core 1 再次读取 `X`。目录发现最新的 `X=2` 在 Core 0 的 `M` 中，于是向 Core 0 发送读 Snoop。

Core 0 返回 `X=2`，从 `M` 降为 `O`；Core 1 得到数据后从 `I` 进入 `S`。目录把 Core 0 记录为 Owner，把 Core 1 记录为 Sharer。内存仍不更新：

```text
Core 0: M -> O, X=2
Core 1: I -> S, X=2
Core 2: I
内存:   X=0
```

现在再次形成了一个 `O` 和一个 `S`，为下一次写权限转移做好准备。

### 2.6 Sharer 写入：`O -> I`、`S -> M`

Core 1 现在要把 `X` 改成 `3`。

Core 1 已经有一份最新的 `S, X=2`，但没有写权限。它向目录请求写权限。目录知道 Core 0 是 Owner，于是：

1. 目录向 Core 0 发送失效 Snoop，要求它放弃 Owner 身份。
2. Core 0 收到 Snoop，从 `O` 变成 `I`，并返回 Snoop 响应。
3. 响应表明 Core 0 已经交出对最新数据的责任。具体实现也可以在响应中携带数据，但 Core 1 已经持有相同的 `X=2`。
4. 目录确认原 Owner 已失效，并把最新数据的责任转移给 Core 1。
5. 目录向 Core 1 授予唯一写权限。
6. Core 1 从 `S` 进入 `M`，然后把 `X` 改成 `3`。

```text
Core 0: O -> I
Core 1: S -> M, X=3
Core 2: I
内存:   X=0
```

这里出现了：

> `O -> I`：原 Owner 放弃脏数据责任和本地副本。

> `S -> M`：共享者取得唯一写权限，并成为新的脏数据持有者。

内存仍然可以保持旧值，因为最新数据的责任已经从 Core 0 转移给 Core 1。

### 2.7 Owner 主动驱逐：`O -> I`

先让 Core 2 读取 `X`。目录向持有 `M` 的 Core 1 发送读 Snoop；Core 1 返回最新的 `X=3` 并进入 `O`，Core 2 得到 `S`：

```text
Core 0: I
Core 1: M -> O, X=3
Core 2: I -> S, X=3
内存:   X=0
```

现在 Core 1 要主动驱逐这条 `O` 缓存行。

Core 1 不能直接丢弃它，因为内存仍是 `X=0`，最新的 `X=3` 由 Core 1 负责。驱逐过程是：

1. Core 1 把最新的 `X=3` 写回目录管理的内存。
2. Core 1 通知目录自己不再是 Owner。
3. 目录确认内存已经更新，并清除 Owner 记录。
4. Core 1 从 `O` 进入 `I`。
5. Core 2 的 `S` 仍然有效，因为它的数据现在与内存相同。

```text
Core 0: I
Core 1: O -> I
Core 2: S, X=3
内存:   X=3
```

这里说明：

> `O` 与 `M` 一样负责最新数据，主动驱逐时不能直接丢弃。本故事选择先写回内存，再进入 `I`。

具体实现也可以把 Owner 身份和最新数据责任转移给另一个共享者。无论采用哪种方式，原 Owner 进入 `I` 前，都必须确保最新数据仍有明确的负责人。

## 3. 回看整个故事

故事中与 `O` 有关的关键变化可以压缩成下面这张表：

| 场景 | Owner 一侧 | 其他核心 | 目录和数据发生了什么 |
|---|---|---|---|
| 其他核心读取 `M` | `M -> O` | `I -> S` | Owner 返回最新数据，内存不必更新 |
| 更多核心读取 | `O -> O` | `I -> S` | Owner 继续供数，目录增加 Sharer |
| Owner 写入 | `O -> M` | `S -> I` | 目录失效所有 Sharer，收齐响应后授权 |
| Sharer 写入 | `O -> I` | `S -> M` | 目录失效原 Owner，并转移脏数据责任 |
| Owner 驱逐 | `O -> I` | `S` 保持 | Owner 写回最新数据，目录清除 Owner |


## 4. 从故事中记住四条规则

1. 一个 `O` 可以与多个 `S` 同时存在，但同一条缓存行最多只能有一个 Owner。
2. 存在 `O` 时，内存可以是旧的，最新数据由 Owner 负责。
3. `O` 不能直接写入；Owner 必须先让所有 `S` 失效，才能从 `O` 进入 `M`。
4. `O` 被失效或驱逐时，最新数据及其责任必须写回内存或转移给另一个节点。

`O` 是操作完成后的稳定状态。等待 Snoop 响应、等待数据返回或等待写回时，真实硬件还需要临时状态，本章不展开。

## 5. MESI 和 MOESI 的区别

完整理解 MOESI 后，再回头比较两个协议。它们最关键的区别发生在“其他核心读取 `M` 数据”时。

### 5.1 MESI 的处理

```text
Core 0: M -> S, X=1
Core 1: I -> S, X=1
内存:   X=1
```

原 `M` 持有者交出最新数据并更新内存，随后所有 Cache 都持有干净的 `S`。

### 5.2 MOESI 的处理

```text
Core 0: M -> O, X=1
Core 1: I -> S, X=1
内存:   X=0
```

原 `M` 持有者变成 `O`，继续负责最新数据。其他 Cache 可以持有 `S`，内存暂时保持旧值。

因此，`O` 状态避免了脏缓存行第一次被共享读取时立即写回内存，也让后续读取者可以直接从 Owner 获得最新数据。
